## Key Decisions Made
- **Decision:** fix the checkers, don't work around formatting.
  - **Context:** my first attempt at #56 used `#[rustfmt::skip]` to keep the mutant patterns matching.
  - **Rationale:** the maintainer said checks must not depend on formatting at all. The skip workaround is parked unpushed on `us-024/format-harden-kernel`; drop it once #61 lands.
- **Decision:** inventories come from a Python lexer, not from the binary.
  - **Context:** the design review weighed having the host binary report its own lists.
  - **Rationale:** that needs a `main.rs` change, which stales claims, and a Linux build. `policy_check` must also never run head code.
- **Decision:** mutants will be matched by token sequence, and the replacement spliced into the original bytes.
  - **Context:** the review considered rustfmt-canonical patterns instead.
  - **Rationale:** no pattern rewrite, so the ratchet doesn't fire, and no dependence on the rustfmt version. It also closes the attack where a nested `rustfmt.toml` makes canonicalisation do nothing.
- **Decision:** the step 4 fingerprint will be `code_tokens(rustfmt(file))`, not raw tokens.
  - **Context:** the step 2 probe found rustfmt changes tokens. It wraps match arms in `{}`, adds `;` and `,`, and reorders `use` items: 19 of 25 files differed.
  - **Rationale:** rustfmt is idempotent, so formatted and unformatted files fingerprint the same. Recorded on #61.
- **Decision:** the mutant file reader is an allowlist.
  - **Rationale:** a blocklist lost three review rounds in a row (`+=`, then `.append`, then aliases).
- **Decision:** keep `policy` enforcement on, even though lane C work is noisy.
  - **Rationale:** the maintainer merges through the PR bypass anyway. Turning enforcement off would let agent auto-merge land checker changes, during the very rewrite of the checkers.
- **Decision:** no `dev` branch.
  - **Rationale:** the full suite only at release loses which commit broke it. The ratchets would fire only on the combined diff. Tags plus `release.yml --strict` are already the release gate.
- **Decision:** `.coderabbit.yaml` is listed explicitly in lane C.
  - **Rationale:** a test requires every tracked file to have a deliberate lane. The file also steers the reviewer.

## Pitfalls & Gotchas
- Every lane C push makes `policy` fail with "needs @jdueadev's approval of the head commit". That's expected, not a bug: check the escalations list is empty and move on. The maintainer merges through the bypass.
- **Don't skip the tool tests on "config-only" changes.** `test_every_tracked_file_has_a_deliberate_lane` checks the file inventory, and #65 failed `check` on it.
- Python edit scripts written through Bash heredocs mangled `\n` inside string literals twice. Prefer the Edit tool for code containing escapes.
- `cargo` in this repo auto-installs the pinned Rust 1.100.0 through rustup.
- The CodeRabbit CLI on Windows is installed under the user's local programs folder, not on Git Bash's PATH. Agent mode can only set the profile; path instructions need the `--detailed` wizard.
- The CLI writes `.coderabbit-recovery-*/` backup folders into the repo root when it saves. The two from this session are already gone; any new ones are untracked and safe to delete.
- CodeRabbit sometimes reviews a stale commit. Check `commit_id` on the comment before acting.
- `const_array_entries` drops doc comments too, which is fine for the tables. `code_tokens` keeps doc comments.
