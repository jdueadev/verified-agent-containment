## How splice_once works (for step 4/5 authors)
- It compares canonical tokens: plain comments are dropped, and layout trailing commas are dropped (`drop_layout_commas`, plus fragment rules for an unbalanced `]`/`}` and a final comma).
- It undoes rustfmt's arm wrap `=> { expr }`. A block is unwrapped only when it holds one expression (no top-level `;`), it is not in a macro, and the next token ends the arm: `,`, a closer, the end, or a path or literal.
- It requires exactly one match and splices the replacement into the original bytes.
- Guards:
  - **Trailing-comma boundary:** a pattern's dropped comma must sit at a real comma or at a closer where a separator could stand (`_separates`). That rules out a block tail, `(x)`, an index, a repeat array and macro groups.
  - **Brace absorption** (`_absorb_blocks`): a match never splits an arm block. A whole-body match that ends in a comma takes in the braces.
  - **Comma restore:** the separator comma is put back when a match takes in a wrapped arm's `}`.
- Tests compare **exact** tokens (`_exact`), not `code_tokens`, which hides `{ b, }`. The kernel test runs rustfmt with `+<channel>` from `rust-toolchain.toml`, at default width and at width 40, and checks that every mutant still parses.
